### 本批修复的根因级 bug
1. **SQLite 不支持 `DateTimeOffset` 出现在 ORDER BY** → `/api/identity/*` 全 500。改用时间有序 Guid v7 主键排序（PG/SQLite 都能翻译）。
2. **菜单循环引用守卫方向写反**：原代码向下遍历 targetParent 子树找 node，实际应沿 `ParentId` 向上追溯祖先链。错误实现导致「父挂到自己子下」返回 204 并造成父子互指、两者都无法删除。
3. **卸载后无法重载**：`UnloadAsync` 置 `Uninstalled`，状态机只允许 `Uninstalled→Discovered`。动态卸载应「停用但留包」→ 回到 `Installed`，`Unloading` 迁移表加入 `Installed`；unload 端点响应改为返回真实 `manager.Get(id).State`。
4. Bit.BlazorUI 10.7.0 API 差异：`BitNavItem.IsDisabled`（非 IsEnabled）；`BitNav.OnSelectItem` 是 `EventCallback<TItem>`，方法组赋值报 CS1503 → 改显式 lambda；`BitCallout` 无 `Color`（未知参数被 CaptureUnmatchedValues 静默变 HTML 属性）→ 改用 Class。

## 修复 VS 报错 MSB4584（MAUI workload 自动导入）
- 现象：VS 错误列表 MSB4584「找不到导入的项目 C:\Program Files\dotnet\packs\Microsoft.Maui.Sdk\11.0.0-rc.2.26505.5\SdkAutoImport.props」，来源 `Microsoft.NET.Sdk.ImportWorkloads.props` 第 14 行，影响多个 Lumen 项目。
- 根因：`global.json`（10.0.100 + rollForward latestMajor + allowPrerelease true）让实际 SDK 落到 **11.0.100-rc.3.26522.148**；VS 预览版残留的 maui-windows workload 注册指向 rc.2 的 MAUI SDK pack，而磁盘上 `Microsoft.Maui.Sdk` 只有 9.0.120/10.0.20/10.0.110/11.0.0-preview.2.26152.10，整个 packs 目录根本没有 `SdkAutoImport.props`。CLI 构建不触发（VS 项目系统的 workload 解析来源不同），所以只有 VS 评估报错。
- 修复（项目级、最小改动）：`Directory.Build.props` 增加 `<MSBuildEnableWorkloadResolver>false</MSBuildEnableWorkloadResolver>`。依据 11 SDK `Sdk.props:51` 先导入 `Microsoft.Common.props`（加载 Directory.Build.props）、`:53` 才导入 `Microsoft.NET.Sdk.props`，其 `:156` 是 `Condition="'$(MSBuildEnableWorkloadResolver)' == 'true'"` 的条件导入；本仓库全是纯 net10.0 项目，不需要任何 workload。`-v:diag` 验证该属性 = false 且不再导入 ImportWorkloads/SdkAutoImport props。
- 顺带修 CS8604：`PlatformConnectionState.Set` 首参由 `string` 改 `string?`（`Normalize(string?)` 本就接受 null，行为不变），`Program.cs:143` 读取 settings.json 时可能拿到 null provider。
- 验证：`dotnet build Lumen.slnx` 0 警告 0 错误；`dotnet test` 13/13 通过。
- **SDK 选型 gotcha**：试过把 global.json 锁回 .NET 10 —— 唯一稳定 SDK 是 10.0.100（10.0.101/10.0.102 目录残缺，SDK resolver 报「未找到」），而 10.0.100 在本仓库构建会在 `Microsoft.Build.Tasks.Copy → DeleteNoThrow → DeleteFilePrivate` 触发 **Stack overflow**；因此 global.json 最终还原为原值（由 latestMajor 落到 11 rc.3，已验证可构建）。等装了完整 .NET 10.0.102+ SDK 再锁回并复测。
- 环境治本（未执行，需用户决定）：VS 安装器修复/重装 .NET MAUI 工作负载或 `dotnet workload repair` 清掉 rc.2 残留；也可在 SDK 目录放 `DisableWorkloadResolver.sentinel` 全局禁用（影响其他项目，不推荐）。改完配置后 **VS 需重启或重新加载解决方案** 才会清除错误列表里的旧评估错误。

## 前端组件运行时注入（免重启，官方插件模式落地）

- 架构（WebHost）：
  1) ModuleAssemblyCatalog（singleton）：_active[moduleId]=(Assembly, ModuleLoadContext?, Version)；Assemblies 惰性集合供 Router.AdditionalAssemblies 绑定；启动 LoadAll（GET /api/modules 激活版本 packagePath）。

  3) 切版本：包版本 > 当前版本才替换（AssemblyName.GetAssemblyName 前瞻），旧 collectible ALC Unload()（活跃线路引用未释放时挂起等 GC——官方 unloadability 行为）。

  5) Routes.razor Router 绑定 ModuleCatalog.Assemblies；Modules.razor 上传/切版本/加载成功后进程内 RefreshModuleAsync(id)。
- 生效方式：切换后**刷新页面**即新版（SSR catch-all 直接新集合；interactive 导航 Router 重建路由表）；当前已打开的页面需刷新。旧版本 DLL 卸载依赖 GC，若活跃线路持有旧组件实例则挂起（内存短期驻留，非泄漏）。
